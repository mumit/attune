# Plan — 2026 H2

Supersedes the sequencing in [future-state.md](future-state.md), whose Phases
1–6 are recorded as shipped in [decisions.md](decisions.md). Evidence for the
priorities here is in [landscape-2026.md](landscape-2026.md). Invariants in
`CLAUDE.md` and [security-architecture.md](security-architecture.md) are
unchanged and constrain every phase below.

## Thesis

Attune's differentiation is **an assistant that earns authority on an evidence
trail its principal can audit, and that cannot be switched off by a vendor.**
Everything else in this market is either free (Gmail AI, Personal Intelligence,
Alexa+ with Prime) or dead (Pulse, Clockwise, Mariner, Atlas, Humane, Katch).

That differentiation currently does not work, for one specific reason: **the
learning loop writes data with the discriminating fields stripped out.** Every
approval writes the string `"[approved] mail: draft_reply on mail"` — no sender,
no subject, no topic. So triage's sender query cannot match, consolidation
cannot derive the per-sender preferences its own prompt asks for, and no eval
noticed because the eval seeds strings the product never produces.

So the sequence is: **close the loop, prove it closes, then make it compound —
and only then widen what the agent may do.** Widening the action surface first
would just produce more actions whose outcomes teach nothing.

Three rules for the whole plan:

1. **No new capability ships without a signal.** Every action must emit a
   decision-ledger row with context attribution, or it is invisible to
   learning and must not be built.
2. **No learning mechanism ships without a metric and a guardrail.** Edit
   burden is the north star; coverage is the paired denominator. The RLUF
   study is the reason (see landscape §5).
3. **Build once.** Nothing new may be implemented separately for the local and
   hosted planes. Where a shared seam does not exist, create it in the same
   change — `hosted/intelligence.py` is the pattern that works.

### P0 — Repair (prompt 24)

Nine defects, all small, several load-bearing.

- `main` is red: 8 failures in `tests/test_attention.py` because
  `JsonAttentionStore._bounded` reads the wall clock and prunes past
  `RETENTION_DAYS=7` while tests pin `T0 = 2026-07-18`. Inject the clock (the
  project's own rule), and do the same for the non-injectable clocks in
  `draft_approve.py`, `grants.py`, `importance.py`, `pending.py`.
- Add a scheduled CI run. The suite went red around 2026-07-25 and nothing
  noticed, because `ci.yml` only fires on push-to-main and PRs.
- `memory-eval.yml` never sets `ATTUNE_EMBEDDING_DIMENSIONS`, which
  `build_mem0_config` raises without. The one live memory-quality signal in the
  project is structurally broken.
- Retrieval precision: pass `min_score` at all four call sites (it exists in
  the interface and is used by no production caller) and stop using the entire
  email body as an embedding query. Context rot means low-precision retrieval
  is actively harmful, not neutral.
- Cap `incoming_summary`. The body is uncapped and transmitted to three
  prompts per message, while the conversational path caps at 1,600 chars.
- Index the audit tail. `_last_hash` linearly scans the whole JSONL on **every
  append** — O(n²) growth on the trust root for autonomy graduation.
- Memoize `importance.assess`. The brief calls it 40+ times per run for ~20
  distinct senders, each a full JSON load under an advisory lock; hosted opens
  a new DB connection per call.
- `brief._meeting_prep` is the one retrieval site that skips
  `frame_memory_text`, violating that function's own documented rule.
- Hoist `grants._recent_decisions`' unbounded `query()` out of its per-grant
  loop.

**Exit:** green suite on a scheduled cron; live memory eval executes; no
production retrieval without a score floor and a bounded query.

### P1 — Reconnect the loop (prompt 25)

- `capture_action_signal` must write sender, subject/topic, and priority into
  both `meta` and `text`. Callers must pass real summaries instead of
  `f"{action} on {domain}"` and a raw thread id.
- Fix the **LOW absorbing state**: a LOW sender is demoted to NOISE, NOISE
  returns before any card is posted, and nothing records a signal on a NOISE
  outcome — so the tier is frozen for 90 days with no recovery but a manual
  pin. Add a probation path and record a weak positive when the principal
  replies manually to a LOW-tier sender.
- `capture_correction` is called without `context`, so every extracted
  preference is scoped to the string `"mail"`. Pass the counterparty.
- Populate `MemoryRecord.created_at/updated_at` (never set today) so anything
  recency-aware becomes possible, and make `list_memories` honour its own
  "most recent" claim.
- Add `valid_from` / `valid_to` / `superseded_by` metadata — the 80% of
  bitemporality that matters, without a Graphiti migration.
- Delete `memory.base.Scope` (exported, referenced nowhere) or use it.

**Exit:** a rejection of a draft to a named sender is retrievable by that
sender's name, and a test proves repeated ignores change a future triage
outcome.

### P2 — Measure (prompts 26, 27)

**26 — the decision ledger.** One append-only row per proposal, and the
single most important field is **`context_attribution`**: which playbook
bullets, memory record ids, and prompt version were in context. Without it you
can log a million interactions and never know what caused a good draft. Also:
`autonomy_rung_granted` / `_used`, `edit_char_distance`,
`edit_distance_normalized`, `edit_sections_changed`, `time_to_decision`, and
`undone`. Undo is the cleanest strong negative and should demote a grant.

**North star:** `mean(edit_distance_normalized | sent)`, plus
approve-without-edit rate and p50 time-to-approve, sliced by domain and sender
tier on a 14-day rolling window. This is the PRELUDE objective, directly
observable, needs no judge.

**Guardrail, mandatory:** **coverage** — proposals per eligible item. Without
it the system reward-hacks into proposing only trivial safe drafts and staying
silent on the hard ones. That is the RLUF failure mode, quantified.

**27 — the eval harness.** Pairwise against what the human actually sent (the
human's version is gold), never absolute Likert scores — the 2026 judge
literature makes absolute judging indefensible as a gate. Hand-label 150–200
pairs, publish judge–human agreement per domain, randomize position, and treat
sub-75% agreement as "not a gate." Add trajectory-level assertions (right tool,
right args, rung respected) since step-level is where agents actually fail.
Every edit and rejection auto-generates a regression case. Run in CI with
per-scorer deltas. Add an injection-resistance suite: Attune's fencing and
provenance controls are good and completely unmeasured.

**Exit:** a dashboard-able north-star number with a coverage denominator, a
regression suite that grows from real decisions, and a published judge
agreement rate.

### P3 — Model layer floor (prompt 28)

`llm.py` is 57 lines of `chat.completions.create`. Across all of `src/`: zero
`tools=`, zero `response_format`, zero `cache_control`, zero streaming.
Structured output is recovered by `json.loads` on free text. This is a
capability floor mislabelled as provider neutrality — and it blocks caching,
which is the dominant cost lever (90% off input on cache hits).

- Extract the seven inline prompt literals into a versioned registry, stamp the
  version into every audit event, and split each prompt into a **stable cached
  prefix** and a volatile suffix.
- Add structured outputs where a contract already exists (triage's
  `PRIORITY:`/`REASON:` two-line parse, the consolidation plan's
  `json.loads(cleaned)`), with the current text parse retained as fallback.
- Add native tool calling behind a capability probe, so gateways that support
  it get it and gateways that don't keep working. Provider neutrality means
  *degrading* gracefully, not refusing the feature.
- Add `max_tokens`, timeouts, and retry/backoff (none exist locally), and read
  `response.usage` so the self-hosted runtime can meter what hosted already
  meters.
- Restore the missing `DRAFT` task to the hosted model gateway — its absence is
  the literal reason hosted cannot draft.

**Exit:** prompts are versioned artifacts; cache-hit rate and token spend are
observable locally; hosted can draft.

### P4 — Compound (prompt 29)

An ACE-style, git-backed playbook — one Markdown file per domain, bullets with
ids, provenance, and helped/harmed counters, written **only** by the nightly
reflector via **incremental delta edits** (full rewrites cause context
collapse), loaded as a **cached prefix** rather than retrieved per request.
Three independent 2026 results say a filesystem the model edits beats a
retrieval index it queries; the ratchet study recorded zero recurrences across
9 error classes.

Safety, non-negotiable:

- **Untrusted email content must never reach a playbook write.** The reflector
  sees the *decision* and the *diff*, with source bodies fenced and marked, and
  may not add a bullet whose text derives from an inbound message body. This is
  the same rule `frame_memory_text` already encodes, applied to a new surface.
- Every bullet carries provenance and a git commit, so a human can `git log`
  the assistant's beliefs and revert exactly one.
- Cap the ratchet: bounded bullets per file, **≤3 new bullets/day**, decay on
  the same 90-day basis as importance signals, and `harmed > helped`
  auto-retirement.

Demote Mem0/Qdrant from "the memory system" to one retriever for facts about
people, projects, and commitments — top-3, high threshold. **Drop the Graphiti
migration** from the roadmap; the evidence no longer supports it.

**Exit:** a measurable drop in edit burden attributable, via
`context_attribution`, to specific bullets.

### P5 — Act (prompts 30, 31)

**30 — capability registry.** Adding one action currently touches 11–13 files
and needs a new compiled LangGraph instance selected by *string-prefix match on
thread_id*. Three graphs exist purely because `draft_fn` differs, and two of
those `draft_fn`s return their input unchanged. Replace with one declarative
descriptor — `(action, domain, connector probe, opt-in flag, propose fn, apply
fn, compensate fn, card renderer, confirmation text, cap, ranker, risk tier)` —
dispatched generically. The hosted plane already models this as
`CapabilityRegistry`; converge on it rather than inventing a third.

Then the actions, in dependency order: generic labels and mark-read → RSVP
accept/tentative → `freebusy` and cross-attendee find-time (today
`propose_free_slots` reads only `primary` in a hardcoded 08:00–18:00 window) →
create event **with** attendees → cancel/delete → recurring-event awareness →
send a new (non-reply) message → reply-all/CC. Chat and Slack must gain a real
write capability; they hold grants in the matrix today with no implementation
behind them.

**31 — reversibility and batching.** Every capability declares a
**compensating action** (re-add `INBOX`, restore the prior event time, delete a
sent-in-error draft) and undo becomes a first-class, audited effect —
`grep -rn undo src/` currently returns nothing. Add an approval **TTL with an
explicit expired state**: today nothing expires a workflow, and a click six
months later still resumes, protected only by the apply-time freshness check.
Hosted already has 15-minute approval and 10-minute dispatch lifetimes. Add
**batch cards** (approve five drafts in one interaction), because the named
counter-risk to approval gates is that approval stops being a decision and
becomes a reflex. Adopt LangChain's Agent Inbox vocabulary — accept / edit /
respond / ignore — since it is now the category's shared language.

**Exit:** a new capability is one descriptor plus tests; every irreversible
effect has a compensating path or is explicitly marked irreversible.

### P6 — Attention budget (prompt 32)

The static daily brief is the product three major vendors measured and retired.
Replace the fixed-cadence brief with **user-authored recurring routines**
(`attune routine add "weekday 8am: unresolved threads from HIGH-tier senders"`)
plus a **global attention budget** — a hard daily ceiling on unsolicited
messages, allocated by ranked importance rather than the current per-feature
`MAX_*_PER_RUN` arrival-order caps. Keep the brief as one shipped default
routine, not as the architecture. Make the scheduler durable while you are
there: `Scheduler._next` is in-memory, never fires on first sight, and has no
missed-run catch-up, so a restart before brief time silently skips the day.

**Exit:** the principal can state what they want proactively, and cannot be
sent more than N unsolicited messages per day.

### P7 — Perform (prompt 33)

The brief is ~64 sequential Google round-trips (10–25s) and is rebuilt from
scratch on every on-demand request; one 25-thread notification batch is ~25
Gmail calls, ~50 model calls, ~50 memory searches, ~125 whole-file JSON reads,
all serial. `list_threads` is N+1 by construction.

Concurrency for independent I/O; `fields=` partial-response masks; Google
`BatchHttpRequest` where available; ETag/`If-None-Match`; an incremental brief
built from the existing snapshot instead of a full re-read; move the hot-path
JSON stores (`pending`, `importance`, `attention`, `nudge`, `graduation`) into
the SQLite database that is already a dependency; cascade triage to a small
model with escalation on low confidence or HIGH-tier senders; and precompute
tomorrow's brief overnight — sleep-time compute gives ~5× less test-time
compute at equal accuracy, and mornings are the most predictable workload
there is. **No semantic caching on the generation path**: a false hit is a
correctness incident when the output gets sent.

**Exit:** brief p50 under 3s; a 25-thread batch under 15s; cache-hit rate
reported.

### P8 — Interoperate (prompt 34)

Migrate `docs/mcp-contract.md` and `connectors/mcp_client.py` to the
2026-07-28 spec: the core goes **stateless** (the `initialize`/`initialized`
handshake and `Mcp-Session-Id` header are gone, client info moves to
per-request `_meta`), and Roots/Sampling/Logging are deprecated. Then **expose
Attune as an MCP server** — importance profile, triage, brief, memory search,
and pending approvals as tools — using the new **Tasks** extension for
approval-gated operations, which is a near-exact match for draft-approve
interrupt semantics. Slack, Calendly, Cal.com, Granola, Glean, and Google
Workspace all already expose servers; being the memory-and-importance layer
other agents call is a stronger position for a one-principal product than
competing as another front door.

Also here: consume meeting context **over MCP** from Granola/Circleback rather
than building capture, which carries live legal exposure (Otter's
non-consensual-recording class action survived a standing challenge in early
2026). And write the deliberate decision to stay out of the browser —
Anthropic measures 11.2% residual prompt-injection success even with
mitigations, and Atlas's deprecation cited injection and URL-handling leaks.
Absence of computer-use should be a recorded choice, not an omission.

**Exit:** Claude, ChatGPT, or Slackbot can ask Attune what matters today and
get an approval-gated action back.

### P9 — Converge (prompt 35)

23,222 LOC in `hosted/` shares **3 imports across 113 modules** with the
19,435-LOC core. Two Google clients, two audit systems, two Slack senders, two
Chat senders, two conversation models, two risk models (`Rung 1-4` vs
`RiskTier R0-R4`), five intent routers, and 39 hand-written app/service/client
files (34.5% of `hosted/`). `control_plane_service.py` is 1,802 lines with 37
inline handlers.

Extract shared cores in this order — connector, model gateway, capability
registry, audit interface, conversation model — each following the
`hosted/intelligence.py` pattern: storage differs per plane, the dataclasses
and rule engine are imported. Unify `Rung` and `RiskTier` into one risk model.
Give the mirrored Slack/Chat brokers a shared base.

**Exit:** a new capability ships to both planes in one change; reuse above 40%.

### P10 — Optimize (prompt 36)

Weekly **GEPA** over the triage and draft prompts against the golden set P2
accumulates, gated on the regression suite in CI. This is where measured gains
come from without touching weights: GEPA beats GRPO by ~10–20% with up to 78×
better sample efficiency, needing hundreds — not tens of thousands — of
rollouts, which one principal genuinely produces.

Only after that is instrumented: a **style LoRA** on accepted/sent drafts
(~$20 on Tinker for a 50M-token run), targeting the one thing context
engineering measurably fails at — informal voice. Note the ceiling: 5-shot
style imitation reaches 96% authorship verification on **email** but 16–66% on
informal domains, and going from 2 to 10 exemplars adds little, so exemplar
retrieval alone plateaus. Use **KTO, not DPO**, for approve/reject data — it
takes unpaired binary labels; DPO needs pairs.

**Do not** pursue RL on weights. **Do not** pursue OpenAI RFT (`o4-mini` only,
platform winding down). **Do not** chase LoCoMo scores — 6.4% of its answer key
is wrong and a full-context baseline beats the memory systems on it.

## What is explicitly not in this plan

- **Graphiti/Neo4j migration.** Removed from the roadmap; evidence no longer
  supports it. Bitemporal metadata on Mem0 records instead.
- **Computer use / browser automation.** Deliberately declined; record the
  reasoning (P8).
- **Ambient meeting capture.** Consume over MCP; do not record (P8).
- **Voice.** Real table stakes, but it is a front door, and Attune's problem is
  not front doors. Revisit after P6.
- **Consumer pricing or a hosted consumer launch.** Gmail AI, Personal
  Intelligence, and Alexa+ are free at a scale Attune cannot reach. The hosted
  plane's value is operated single-tenancy for people who want the audit trail,
  not a $20/mo subscription.
- **Any new `hosted/` module that has no local counterpart.** Rule 3.

## Success criteria for the half

1. `mean(edit_distance_normalized | sent)` falls measurably, with coverage flat
   or rising, and the fall is attributable to named playbook bullets.
2. At least one autonomy grant graduates in-product, on evidence, without a
   terminal command — and at least one demotes automatically.
3. Every irreversible effect has a compensating action or is marked
   irreversible in its descriptor.
4. Brief p50 under 3 seconds.
5. Another agent can call Attune over MCP and receive an approval-gated result.
6. A capability added once appears in both deployment planes.
